# CDW · Command Data Workspace

터미널 명령어의 stdout을 Polars로 표로 변환하고 DuckDB에 저장하는 로컬 데스크톱 앱입니다.
Python **3.12.14**, QtPy **2.4.3**, PySide6 **6.9.3**, DuckDB **1.4.3**, Polars **1.36.1**, PyArrow **22.0.0**, pytz **2026.6**을 사용합니다. pytz는 DuckDB의 시간대 포함 날짜·시각을 Python 값으로 읽는 데 필요하며 폐쇄망 설치 목록에도 포함합니다.
대상은 **RHEL 8.10 x86_64 폐쇄망**이며, 현재 개발 환경에서는 Windows에서 실행·검증합니다.

## 실행

이 작업 폴더에는 Python 3.12.14 기반 `.venv`가 준비되어 있습니다.

```powershell
.venv\Scripts\python.exe -m cdw
```

새 개발 환경에서는 Python 3.12.14로 다음과 같이 설치합니다.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m cdw
```

다른 작업 환경을 쓰려면 `python -m cdw --data-dir /absolute/path/to/workspace`를 사용합니다.
기본 폴더는 Linux `$XDG_DATA_HOME/cdw` 또는 `~/.local/share/cdw`, Windows `%LOCALAPPDATA%/cdw`입니다.
`CDW_DATA_DIR` 환경변수로도 선택할 수 있습니다. 명령행 옵션이 우선합니다.
설치 후에는 CLI는 `cdw`, GUI는 `cdw-gui` 또는 `python -m cdw`로 실행합니다. 실제 구현과 실행 진입점은 모두 `src/cdw`에 있으며 제품명은 `branding.py`에서 한 번 정의합니다.
0.3부터 CDB 실행 명령·환경변수·패키지 별칭과 이전 설정의 자동 변환을 제공하지 않습니다. 기본 작업 폴더는 `cdw`이며 예전 폴더에 자동 연결하지 않습니다. 이전 데이터 파일을 이동하거나 삭제하지는 않습니다.

## 1분 데모

1. 사이드바에서 **SQL 워크스페이스 → 프리셋 등록 → 데모 채우기 → 등록**.
2. **지금 수집**을 누릅니다. 가상의 서버 상태 5행이 `source.host_inventory`에 저장됩니다.
3. **SQL 실행**을 누르거나 다음 SQL을 입력하고 `Ctrl+Enter`를 누릅니다.

```sql
SELECT hostname, cpu_percent, memory_percent, status
FROM source.host_inventory
WHERE cpu_percent >= 30
ORDER BY cpu_percent DESC;
```

데모는 실제 장비를 스캔하지 않으며, `python -m cdw.sample_command`가 고정 샘플 JSON을 출력합니다.
프리셋의 **파싱 및 저장** 탭에서 파일 또는 메모리 저장을 선택할 수 있습니다.
조회할 때마다 `host_inventory`, `host_inventory (2)`처럼 결과 탭이 추가됩니다. 열 제목의 필터 버튼으로 조건을 적용한 뒤 **공유**, **작업**, **저장**을 사용할 수 있습니다. **저장**에서 `selected_hosts`로 저장하면 이후 `SELECT * FROM memory.selected_hosts`로 조회할 수 있습니다.

## 현재 제공 범위

- 기본 레이아웃: 사이드바, 페이지 영역, 한 줄 상태/로그 바. 로그 바 어디든 클릭하면 전체 로그 팝업이 열립니다. 키보드 포커스 상태에서는 Enter·Space로도 열 수 있습니다.
- 사이드바 상단 화살표로 접기·펼치기. 접으면 아이콘만 표시하고 호버 툴팁으로 이름을 확인합니다. 펼친 상태에서 오른쪽 경계선을 드래그해 너비를 조절하며, 접었다 펼쳐도 조절한 너비를 복원합니다. 사이드바 배경색은 페이지 배경과 별도로 정의합니다. 로그 바 높이는 현재 글꼴 높이와 얇은 내부 여백으로 계산합니다.
- 홈: 프리셋 수, 최근 실행 상태, 실행 이력과 상세 오류·stderr.
- 프리셋 등록/편집: 실행 파일, 인자, 작업 디렉터리, 환경변수, 출력 형식·인코딩, 저장 정책, 시간·출력 제한.
- 명령어 실행/취소: stdout과 stderr를 각각 읽고 종료 코드·시간·크기를 검증합니다.
- JSON / NDJSON / CSV / 텍스트 → Polars → Arrow → DuckDB.
- 파일/메모리 저장, 전체 교체/행 추가, 접근 가능한 테이블의 타입·이름·업데이트 시각과 컬럼 목록.
- 단일 SELECT 실행마다 전체 결과 스냅샷을 새 탭으로 표시. 같은 원본 이름에는 번호를 붙이며, 프리셋을 바꾸어도 기존 결과를 유지합니다.
- 열별 값 선택·검색, 숫자/날짜 범위, 정규 표현식, 날짜 트리와 오름차순/내림차순 정렬.
- 결과의 텍스트/HTML 복사, 구분자 지정 CSV·JSON·DuckDB 내보내기, 이름을 지정한 메모리 테이블 저장.
- 작업 등록·편집·삭제 및 조회 결과를 JSON/CSV 임시 파일로 전달하는 로컬 명령 실행·취소.
- 실행 이력 영속화와 비정상 종료 후 상태 복구. 앱의 데이터 폴더별 단일 프로세스 잠금.
- CLI로 동일한 등록·수집·조회 계약 사용.
- Heroicons 선형·채움형, 상속 기반 공통 위젯/레이아웃과 중앙 디자인 시스템.
- 색 테마, 라이트/다크, 화면/SQL 글꼴, 글자 크기, UI 배율의 즉시 적용·자동 저장.
- 설정 페이지의 디자인 미리보기와 기본값 복원.

스케줄러, 데이터 셀 편집, 여러 SQL **편집기** 탭, 사용자 계정은 후속 범위입니다. SQL 편집기는 현재 하나이며, 조회 **결과** 탭은 여러 개를 열 수 있습니다.

## 데이터 계약

| 항목 | 동작 |
|---|---|
| 명령어 | 실행 파일과 인자 목록을 분리하고 `shell=False`로 실행합니다. 인자는 한 줄에 하나이며 따옴표를 덧붙이지 않습니다. stdin은 닫혀 있으므로 대화형 명령은 지원하지 않습니다. |
| 환경 | 현재 환경에 프리셋 환경변수를 덮어씁니다. cwd를 생략하면 앱 실행 위치를 상속합니다. 운영 프리셋에는 절대 경로와 cwd를 명시하는 것을 권장합니다. |
| 파이프 | `/bin/bash`를 실행 파일로, `-c`와 스크립트 전체를 별도 인자로 명시합니다. 프리셋의 명령은 앱 사용자 권한으로 실행됩니다. |
| 출력 | stdout만 데이터로 파싱합니다. stderr는 진단 이력에 저장합니다. 기본 제한은 둘을 합해 16 MiB, 60초입니다. |
| JSON | 객체 하나 또는 객체 배열. NDJSON은 한 줄에 객체 하나. 컬럼·자료형은 전체 출력을 대상으로 추론합니다. |
| CSV | 첫 행은 고유하고 비어 있지 않은 헤더. 구분자는 UTF-8 한 바이트 문자. 날짜는 자동 변환하지 않습니다. |
| 텍스트 | `line_number`, `text` 두 컬럼으로 변환합니다. |
| 빈 데이터 | 오류로 처리하며 기존 테이블은 유지합니다. 종료 코드가 0이 아니거나 파싱이 실패해도 저장하지 않습니다. |
| 저장 | 테이블은 `source.<소문자_테이블명>`. 전체 교체는 트랜잭션으로 교체합니다. 추가는 컬럼 순서·이름·DuckDB 자료형이 정확히 같아야 합니다. |
| 중복 | 프리셋 이름과 `(저장 대상, 테이블)` 조합은 각각 유일합니다. 동일 ID로 저장하면 해당 프리셋을 편집합니다. |
| 메모리 | 수집 테이블과 저장한 결과 테이블은 같은 앱 세션에서 공유합니다. 페이지·프리셋 이동에는 유지되며 앱 종료 시 삭제됩니다. 프리셋 설정 자체는 남습니다. |
| 파일 | 앱 재시작 후에도 유지됩니다. 프리셋의 저장 대상/테이블 이름 변경은 기존 데이터를 삭제하거나 이동하지 않습니다. |
| SQL | 하나의 SELECT 또는 SELECT를 반환하는 WITH만 지원합니다. DDL/DML/다중 문장은 거부합니다. GUI는 전체 결과를 보존하고, CLI `query`만 최대 500행 미리보기를 반환하며 잘림 여부를 포함합니다. |
| 조회 스냅샷 | 원래 SQL을 한 번 실행한 결과를 보관합니다. 이후 원본 테이블을 수집·교체해도 기존 탭의 값은 바뀌지 않으며, 복사·내보내기·저장은 SQL을 재실행하지 않습니다. 중복 컬럼명은 DuckDB가 고유한 이름으로 정규화합니다. |
| 결과 저장 | 현재 탭의 필터·정렬 결과를 `memory.<소문자_테이블명>`으로 복사합니다. 자료형과 빈 결과의 스키마를 보존하며 같은 이름은 덮어쓰지 않습니다. 결과 탭을 닫아도 저장한 테이블은 유지됩니다. |
| 결과 사용 범위 | 공유·작업·저장은 현재 탭의 필터와 정렬을 적용한 전체 행을 사용합니다. 선택한 셀이나 화면에 보이는 행만 대상으로 삼지 않습니다. |
| 취소 | 명령어 실행은 취소할 수 있습니다. 파싱 후 저장 전에도 취소를 확인합니다. 이미 시작된 저장 트랜잭션은 완료하며, SQL 실행은 DuckDB interrupt를 사용합니다. |

SQL 편집기는 신뢰하는 사용자의 로컬 분석 도구입니다. SELECT 제한은 보안 샌드박스가 아니며 DuckDB 파일 읽기 함수 등에 대한 접근 격리를 제공하지 않습니다.
GUI는 결과를 DuckDB 세션과 테이블 모델에 보관하므로 전체 행 수에 따라 메모리 사용량이 늘어납니다. 큰 조인은 WHERE/LIMIT 등으로 범위를 정하고, 사용이 끝난 결과 탭을 닫으세요. CLI의 미리보기 제한도 쿼리 자체의 연산량을 제한하지는 않습니다.
프로세스 출력 제한도 파싱 이후 메모리 사용량의 상한은 아닙니다.

프리셋은 로컬 `metadata.sqlite`에 저장되며 환경변수를 암호화하지 않습니다. 비밀 값은 외부 환경에서 주입하세요.
명령어 인자와 stderr에도 비밀 값이 들어가지 않게 구성하세요. 실행 이력 스냅샷에서는 환경변수를 제외합니다.
앱이 파일 DB를 사용하는 동안 다른 프로세스가 같은 DB를 쓰지 않도록 해야 합니다. 여러 작업 환경이 같은 DB 파일을 공유하는 구성은 지원 범위가 아닙니다.

## 결과 탭과 테이블 목록

프리셋 드롭다운은 **저장 방식 아이콘 + 프리셋 이름**만 표시합니다. 메모리는 칩, 파일 저장은 폴더 아이콘이며 현재 테마와 UI 배율을 따릅니다. 프리셋 아래 목록은 등록된 프리셋의 실제로 존재하는 접근 가능한 DB 파일과 현재 세션 메모리의 테이블을 함께 보여줍니다. 파일 DB의 `source` 밖에 있는 사용자 테이블·뷰도 포함합니다. 임의 폴더의 DB 파일을 자동 검색하지는 않습니다.

| SQL 이름 | 대상 |
|---|---|
| `source.host_inventory` | 현재 선택한 프리셋의 DB 안에 있는 수집 테이블 |
| `memory.source.host_inventory` | 메모리 프리셋으로 수집한 테이블 |
| `memory.selected_hosts` | 결과의 **저장** 버튼으로 만든 세션 테이블 |
| `db_<파일명>_<경로해시>.source.host_inventory` | 목록에 표시된 파일 DB의 테이블. 다른 프리셋을 선택해도 이 이름으로 조회·조인 가능 |

파일의 SQL 이름은 경로에서 계산하며 특수 문자가 있는 식별자는 따옴표로 표시합니다. 목록에는 짧은 테이블명을 표시하고 전체 SQL 이름과 파일 경로는 툴팁으로 확인할 수 있습니다. SQL에서는 이 전체 이름을 사용하세요. 프리셋 없이도 `SELECT 1`이나 `memory.<이름>`을 조회할 수 있습니다. 목록의 업데이트 시각은 앱에서 수집·저장한 시각을 우선 사용하고, 외부 파일 테이블은 확인 가능한 파일 수정 시각을 사용합니다.

탭 제목은 SQL 파서로 해석한 첫 FROM 원본 이름입니다. CTE를 조회하면 CTE 이름, 조인은 첫 원본 이름을 사용하며 원본이 없으면 `결과`를 사용합니다. 같은 제목은 `(2)`, `(3)` 순서로 구분합니다. 각 탭은 자체 필터·정렬 상태를 유지합니다.

열의 필터 버튼 또는 해당 열에서 `Alt+↓`를 누르면 실제 SQL 자료형에 맞는 조건을 엽니다. 팝업에는 필터 종류와 원래 자료형을 표시합니다. 여러 열의 조건은 모두 만족해야 하며, 한 열에서는 값 선택과 조건이 함께 적용됩니다.

| 컬럼 자료형 | 제공하는 조건 |
|---|---|
| 숫자 | 같음·같지 않음, 이상·이하·초과·미만·사이(양 끝 포함) |
| 날짜·날짜/시각 | 같음·같지 않음, 이전·이후(포함/제외)·사이, 연도 → 월 → 일 값 선택 |
| 시각(`TIME`, `TIMETZ`) | 시각 비교·범위. `HH:MM[:SS]`, 소수 초와 시간대 입력 지원 |
| 문자 | 같음·같지 않음, 포함·시작·끝, 정규 표현식, 빈 문자열 |
| 논리값 | 참/거짓 선택으로 같음·같지 않음 |
| 배열·구조체 등 기타 | 값 목록에서 선택 |

모든 자료형에서 NULL 여부와 값 목록 선택을 사용할 수 있습니다. 날짜처럼 보이는 `VARCHAR`도 문자 필터를 사용합니다. 날짜·시각 조건에 날짜만 입력하면 그날 00:00이며, 시간대가 있는 조건은 UTC로 비교합니다(시간대 생략 시 UTC로 해석). 자정을 넘는 시각 범위는 한 조건으로 표현하지 않으므로 SQL의 OR 조건을 사용하세요. 문자 포함·시작·끝은 대소문자를 구분하지 않으며, 정규식은 기본적으로 구분하고 `(?i)`로 무시할 수 있습니다. 잘못된 조건은 안내하고 기존 필터를 유지합니다. 필터·정렬은 보관된 결과에 적용되므로 원본 DB를 변경하지 않습니다.

## 공유 및 작업 입력

**공유**에서 텍스트 복사는 헤더를 포함한 탭 구분 텍스트를, HTML 복사는 표와 일반 텍스트를 클립보드에 넣습니다. CSV와 JSON 파일은 UTF-8이며 CSV 구분자는 줄바꿈·따옴표·NUL을 제외한 문자 하나입니다. 구분자 입력에 `\t`를 쓰면 탭으로 해석합니다. 수집 프리셋의 CSV 파서 구분자 제한과 내보내기 구분자 계약은 별개입니다.

JSON 내보내기는 컬럼명을 키로 하는 객체 배열입니다. 날짜·시간은 ISO 문자열, Decimal은 정밀도를 보존한 문자열, BLOB은 `{"$binary":"base64 내용"}`으로 표현합니다. 리스트·구조체는 중첩 JSON으로, NaN/Infinity는 문자열로 표현합니다. CSV·HTML도 같은 텍스트 변환을 사용하되 NULL은 빈 셀입니다. DuckDB 내보내기는 `result` 테이블 하나를 만들고 SQL 자료형·NULL·빈 결과의 스키마를 보존합니다.

파일은 임시 파일을 완성한 뒤 교체하며 실패하면 기존 출력 파일을 유지합니다. 사용 중이거나 프리셋에 등록된 원본 DB와 `metadata.sqlite`에는 내보낼 수 없습니다.

**작업** 페이지에서 이름, 실행 파일, 한 줄에 하나씩 인자, 작업 디렉터리, 환경변수, 입력 형식(JSON/CSV), 시간·출력 제한을 등록합니다. 인자에는 `{input}`을 포함해야 합니다. 결과 탭의 **작업** 버튼에서 실행할 작업을 선택하면 그 자리를 UTF-8 임시 입력 파일의 절대 경로로 치환합니다. 예를 들어 실행 파일 `python3.12`, 인자 두 줄 `/opt/tools/analyze.py`와 `{input}`으로 연결할 수 있습니다.

JSON 작업 입력은 내보내기 객체 배열과 달리 다음 봉투 형식이며, 스칼라 인코딩 규칙은 위와 같습니다.

```json
{"columns":["hostname","cpu_percent"],"types":["VARCHAR","DOUBLE"],"rows":[["server-01",42.5]]}
```

CSV 작업 입력은 헤더와 데이터 행이며 등록한 구분자를 사용합니다. 명령은 수집과 같은 `shell=False` 실행·환경·시간/출력 제한을 사용하고 stdin은 닫습니다. 작업이 끝나거나 실패·취소되면 입력 파일은 삭제하므로 작업 프로세스가 실행 중에 읽어야 합니다. stdout/stderr와 실행 상태는 세션 로그에서 확인할 수 있습니다. 작업 설정은 `metadata.sqlite`에 유지되며, 작업 출력이 자동으로 새 데이터 테이블에 저장되지는 않습니다.

1. 의미는 `domain`에서 정의하고 UI·CLI가 같은 계약을 사용합니다.
2. 기본 정책은 `config`, 사용자별 정책은 프리셋에서 선택합니다. runner/store가 전달받은 값을 집행합니다.
3. 프리셋 원본은 SQLite에만 있습니다. UI는 저장 후 다시 읽습니다. 데이터 원본은 DuckDB입니다.
4. subprocess·Polars·DuckDB·SQLite의 세부사항과 오류는 각 어댑터에서 해석합니다.
5. UI·CLI의 `save_preset`, `collect`는 같은 서비스를 사용합니다. 전체 스냅샷은 `query_workspace`, CLI 미리보기는 `query`로 동작을 구분합니다.
6. 테스트는 실제 명령어를 실행하고 서비스·CLI·UI에서 사용자에게 보이는 저장 결과를 검증합니다.
7. 정책 기본값은 config 상단, SQL·파싱 규칙·OS 처리값·UI 문구/스타일은 각 소유 모듈 상단에 둡니다.

공개 결과 계약은 `ApplicationService.query_workspace`, `workspace_tables`, `save_result_table`, `copy_result`, `export_result`, `release_result`에서 검증합니다. 후속 동작은 `QuerySnapshot.id`와 원본 행 인덱스를 받아 같은 스냅샷을 사용합니다. `TaskService`는 `TaskDefinition`과 전체 `QueryResult`를 사용하며 잘린 미리보기를 작업 입력으로 거부합니다. `tests/test_workspace_backend.py`는 500행을 넘는 전체 결과, 원본 변경 후 스냅샷 유지, 자료형·빈 스키마, 카탈로그와 안전한 파일 교체를 실제 DuckDB로 검증합니다.

## 디자인 시스템과 설정

사이드바 **설정**에서 다음 항목을 변경할 수 있습니다. 변경 즉시 열린 페이지와 다이얼로그에 적용하고, 현재 작업 환경의 `metadata.sqlite`에 자동 저장합니다.

| 사용자 설정 | 제공 범위 |
|---|---|
| 화면 모드 | 라이트, 다크 |
| 강조 색·배경 색·보조 배경 색·전경 색 | `#RRGGBB` 직접 입력 또는 색상 선택창. 라이트·다크별로 저장 |
| 글꼴 | 장비에 설치된 화면 글꼴 / SQL·명령어 글꼴을 각각 선택 |
| 기본 글자 크기 | 8–20pt |
| UI 배율 | 80–150% |

**디자인 미리보기**에서 버튼·입력창·아이콘·SQL·테이블을 함께 확인할 수 있습니다. **기본값으로 복원**도 즉시 저장됩니다.
다크 기본색은 패널 `#141719`, 페이지·일반 위젯 배경 `#202020`, 보조 배경 `#292d30`입니다. 보조 배경은 탭 헤더·표 헤더·표의 교차 행·다중 행 편집기·카드에 적용해 영역을 구분합니다. 라이트 기본 보조 배경은 `#e7ebf1`입니다. 강조 버튼·선택·호버 상태는 구분되는 상태색을 사용합니다. 배경색을 직접 바꾸어도 다크 패널은 첫 번째 기본색을 유지합니다.
하단 로그 바는 사용자 지정 배경색과 별개로 현재 모드의 두 번째 기본 배경색을 사용합니다. 다크에서는 `#202020`을 유지하며, 마우스를 올려도 사용자 지정 배경색으로 바뀌지 않습니다.
색상 직접 입력은 Enter 또는 포커스 이동 시 적용합니다. 빈칸은 테마 기본값을 사용합니다. 전경 색은 기본 글자·아이콘에 적용되고, 보조 글자·테두리·호버·선택 상태는 지정한 색에서 계산합니다. 강조 버튼의 글자는 해당 강조 색에서 읽기 쉬운 밝기색을 사용합니다. 선택창 취소나 잘못된 HEX 입력은 저장된 색을 바꾸지 않습니다. 강조 색은 모드별 기본색 또는 사용자 지정 색만 사용합니다.
화면 설정은 현재 v4 형식만 읽고 저장합니다. 이전 형식은 안내 후 기본 화면 설정으로 열며, 설정에서 새로 저장하기 전까지 원본 기록을 변경하지 않습니다.
저장 실패 시 실행 중인 테마를 유지하고 설정 입력을 되돌립니다. 손상된 화면 설정은 기본 테마로 열고 안내하며, 사용자가 설정을 저장하기 전에는 기존 기록을 덮어쓰지 않습니다.
글꼴은 별도 다운로드하지 않습니다. 다른 장비에 해당 글꼴이 없으면 Qt가 대체 글꼴을 사용하고 설정 목록에 미설치를 표시합니다.

**역할과 원본**

- `AppearanceSettings`: 사용자 설정만 담는 불변 계약. padding/spacing/반경 같은 내부 항목은 저장하거나 입력받지 않습니다.
- `ColorOverrides`: 모드별 강조·배경·보조 배경·전경 색의 검증과 정규화 계약. 빈 값은 테마 기본값을 뜻합니다.
- `STYLE_SPEC`: 색상 역할과 위젯/레이아웃 규칙의 유일한 원본. `MetricRule`은 고정, 배율 적용, 범위 제한 배율을 구분합니다.
- `ResolvedStyle`: 사용자 설정과 내부 규칙으로 계산한 읽기 전용 스냅샷. 실제 글자 크기는 `기본 크기 × UI 배율 × 글꼴 역할 비율`입니다.
- `ThemeManager`: 저장 성공 후 팔레트·글꼴·QSS를 적용하고 변경 신호를 보냅니다. 페이지가 직접 전역 스타일을 수정하지 않습니다.
- `Cdw*` 위젯/레이아웃: 생성 시 현재 스타일을 적용하고 변경 신호를 구독합니다. 예를 들어 `CdwButton`은 `QPushButton`, `CdwVBoxLayout`은 `QVBoxLayout`을 상속합니다.

새 페이지는 `CdwPage`를 상속하고, 입력·버튼·레이아웃은 `widgets.py`의 공통 클래스를 사용합니다. 클래스와 스타일 속성도 `Cdw`·`cdw` 이름으로 통일합니다.
페이지는 `primary`, `navigation`, `card`, `page` 같은 **역할**만 선택합니다. 색상값이나 padding을 페이지에서 지정하지 않습니다.
페이지와 사이드바의 메인 제목·설명은 `CdwTitleArea`로 묶습니다. 제목 영역과 기능 영역·사이드바 메뉴는 같은 `section_padding`을 사용하여 왼쪽 시작점을 맞추며, 접기 버튼 등은 제목 영역의 `header` 오른쪽에 추가합니다. 안내 문구 하나만 있는 경우에는 `CdwLabel`의 `padding_role`로 같은 여백을 적용하므로 별도의 영역 위젯으로 감싸지 않습니다.
페이지 안의 기능 영역은 `CdwSection(title)`으로 만들고, 자식 위젯은 이 객체의 `content`에 추가합니다. 영역은 바깥 테두리 없이 상단 제목을 표시하며, 관련 버튼·보조 정보는 `header`에 추가합니다. 영역 자체가 안쪽 여백을 소유하므로 별도의 패딩 레이아웃을 중첩하지 않습니다.

`CdwTabWidget`은 탭 바와 내용 영역 전체를 하나의 공통 곡률 테두리로 감쌉니다. 헤더의 위·좌·우 바깥 여백은 없으며, 선택한 탭과 바깥 프레임이 공유하는 테두리는 한 번만 그립니다. 선택한 탭은 위쪽 모서리의 공통 곡률을 사용하며 아래쪽은 열어둡니다. 헤더와 내용 사이의 구분선은 선택한 탭 아래에서만 끊겨 내용과 이어지며, 탭 전환·이동·스크롤에 맞춰 갱신됩니다. Qt의 별도 바닥 선은 표시하지 않습니다. 결과 표는 `set_embedded(True)`로 자체 테두리·바깥 여백을 제거하여 탭 컨테이너와 연결합니다. 프리셋 아래의 별도 저장 타입·테이블명·성공 시각 줄은 표시하지 않으며, 테이블 정보는 사용 가능한 테이블 목록에서 확인합니다.
위젯 하나만 배치할 때는 `CdwSection`으로 감싸지 않고 페이지나 분할 영역에 위젯을 직접 추가합니다. 테이블 목록과 안내 페이지에도 이 규칙을 적용합니다.
일반 위젯은 공통 `radius`를 사용하고, 호버 툴팁·드롭다운 목록·메뉴 같은 떠 있는 창의 바깥 모서리는 별도 `popup_radius`를 `0`으로 고정합니다. 영역 마스크·반투명 창을 만들지 않고 팝업·툴팁의 페이드/애니메이션도 사용하지 않습니다. 테이블은 공통 반경만큼 내부를 띄워 자식 헤더가 둥근 프레임을 덮지 않도록 합니다. 사내 RHEL에서 그래픽 실물 검증은 별도로 필요합니다. [Qt의 마스크 및 반투명 창 제약](https://doc.qt.io/qt-6/qwidget.html#setMask)을 참고하세요.
툴팁·드롭다운·컨텍스트 메뉴의 바깥 테두리와 그림자는 제거하고, 현재 테마의 공통 배경색을 사용합니다. `PopupStyleFilter`가 Qt가 생성하는 팝업에도 표시 전 공통 창 규칙을 적용하므로 페이지마다 별도 처리를 넣지 않습니다. 마우스 선택·키보드 이동·Escape 닫기 동작은 유지합니다.
한 줄 입력 필드·드롭다운·숫자 입력창은 아래쪽 선만 표시하고, 이처럼 하단 테두리만 있는 위젯은 `underline_radius`를 `0`으로 고정합니다. 통합 버튼에도 같은 규칙을 적용합니다. SQL 편집기 등 다중 행 입력창은 네 방향 테두리와 공통 `radius`를 사용합니다. 드롭다운·숫자 입력창의 버튼은 별도 테두리 없이 부모 필드 오른쪽 끝에 통합하고 Heroicons 화살표를 그립니다. 파일 선택 입력창은 `CdwActionLineEdit`를 사용해 동작 버튼을 필드 안에 배치합니다.
고정 영역 배치는 `CdwSectionGroup.add_section()`을 사용하며, 이 그룹은 인접 영역 사이에만 독립된 `CdwDivider` 구분선을 넣습니다. 크기를 조절하는 영역은 `CdwSectionSplitter`를 사용하여 동일한 구분선과 영역 간격을 적용합니다. 구분선은 영역의 테두리가 아니며, 양 끝에 영역 안쪽과 같은 `section_padding`을 적용합니다. 가로선은 좌우, 세로선은 상하를 띄우며 드래그 핸들의 조작 범위는 유지합니다. 사이드바 경계는 전체 높이를 사용하는 별도 경계선입니다. 페이지 바깥 여백·영역 안쪽 여백·영역 간격은 `spec.py`에서만 정의하며, UI 배율과 내부 최소·최대 규칙에 따라 함께 갱신됩니다.
공통 규칙을 추가할 곳은 `spec.py`와 `widgets.py`의 적용 훅입니다. Qt가 내부적으로 생성하는 스크롤바·팝업·파일 선택창 자식 등은 Qt 경계에서 같은 QSS/팔레트/글꼴을 적용합니다.
영역 안의 기본 정렬은 왼쪽입니다. 공통 가로 레이아웃은 일반 위젯을 왼쪽부터 배치하며, 입력·라벨·폼·표 헤더도 같은 방향을 사용합니다. 명시적으로 오른쪽에 배치한 헤더 작업 버튼과 숫자 셀의 정렬은 유지합니다. 편집기와 표 등 확장 가능한 위젯은 사용 가능한 너비를 채웁니다.
버튼에는 포커스를 받았다는 이유만으로 강조 테두리를 추가하지 않습니다. 키보드 포커스와 Tab·Space·Enter 조작은 유지합니다.
스타일 객체는 데이터 계약이며 Qt의 `QStyle`을 직접 교체하는 사용자 설정 객체가 아닙니다.

글자 크기 변화에 따라 컨트롤·테이블 행의 최소 높이를 계산합니다. 큰 배율에서는 페이지/다이얼로그의 스크롤로 내용을 계속 접근할 수 있습니다.
SQL 편집기와 디자인 미리보기는 공통 `CdwSqlEditor`를 사용합니다. 코드 글꼴을 유지하면서 `SQL_CODE` 역할의 내부 비율(1.2)을 적용하고, 기본 글자 크기와 UI 배율 변경을 함께 반영합니다.
위젯 치수는 논리 픽셀로 계산합니다. 화면의 DPI는 Qt가 처리하며 앱 배율 계산에 다시 곱하지 않습니다.
아이콘은 SVG를 그리는 `QIconEngine`으로 요청된 DPI에 맞춰 렌더링합니다. 일반 아이콘은 outline, 선택된 내비게이션은 solid이며 상태별 색상은 버튼과 같은 색상 역할을 사용합니다.

**아이콘 출처**: [Heroicons v2.2.0](https://github.com/tailwindlabs/heroicons/tree/v2.2.0), Tailwind Labs, MIT.
26종의 선형/채움형 SVG 52개, 원본 `LICENSE`, 출처 및 SHA-256 목록을 패키지에 포함합니다. 앱 실행 시 네트워크 요청은 없습니다.
`scripts/vendor_heroicons.py`는 개발자가 명시적으로 자산을 다시 가져올 때만 사용하는 도구입니다.
메타데이터는 현재 v2 스키마를 사용합니다. 빈 DB는 현재 스키마로 초기화하고 다른 버전의 DB는 변경 없이 거부합니다. 이전 버전에서 사용하던 작업 폴더는 자동 업그레이드하지 않습니다.

DuckDB는 하나의 엔진 스레드가 메모리 연결과 부착된 파일 카탈로그를 생성·사용·종료합니다. 결과 스냅샷은 메모리에 보관하고 원본 파일의 조회용 뷰는 임시로만 생성합니다. Qt 위젯과 테이블 모델은 GUI 스레드에서만 변경합니다.
수집 시 DuckDB 트랜잭션 안에서 데이터와 커밋 식별자를 함께 기록합니다. SQLite와 DuckDB를 하나의 트랜잭션으로 취급하지 않습니다.
파일 저장 후 이력 갱신 전에 비정상 종료되면 다음 시작에서 커밋 식별자로 성공 여부를 복구합니다. 저장 전 중단/메모리 실행은 중단으로 기록합니다.

## CLI

```bash
python -m cdw.cli --data-dir /tmp/cdw-demo demo
python -m cdw.cli --data-dir /tmp/cdw-demo presets
python -m cdw.cli --data-dir /tmp/cdw-demo collect <preset-id>
python -m cdw.cli --data-dir /tmp/cdw-demo query <preset-id> --sql 'SELECT * FROM source.host_inventory;'
python -m cdw.cli --data-dir /tmp/cdw-demo history
python -m cdw.cli --data-dir /tmp/cdw-demo register preset.json
```

`demo` 출력은 버전 1 프리셋 JSON 예시로 사용할 수 있습니다. `register`는 같은 ID면 수정합니다.
stdout은 JSON 결과, stderr는 JSON 오류입니다. 종료 코드는 성공 0, 오류 1입니다.
CLI `query`는 기존과 같이 최대 500행을 반환하고 `truncated`로 잘림 여부를 알립니다. GUI 결과 탭의 전체 결과·공유·작업과 범위가 다릅니다.
CLI 명령은 각각 별도 프로세스이므로 메모리 수집 결과를 다음 CLI 호출에서 조회할 수 없습니다. 메모리 분석은 GUI 또는 같은 서비스 인스턴스를 사용하세요.
GUI와 같은 데이터 폴더를 사용하는 CLI는 GUI를 종료한 뒤 실행합니다.

## 테스트

```bash
python -m pytest
```

Qt UI 테스트는 `offscreen` 플랫폼에서 실제 위젯을 조작합니다. RHEL에서는 추가로 X11/Wayland 데스크톱에서 창 실행을 확인해야 합니다.
폐쇄망 반입·설치 절차는 `scripts/build_offline_bundle.sh`, `scripts/install_offline.sh`를 참고하세요.

## RHEL 8.10 폐쇄망 반입

`requirements/runtime.lock`는 `pyproject.toml`에서 **Python 3.12 / x86_64-manylinux_2_28 / binary-only**로 생성한 해시 포함 목록입니다.
PySide6는 6.9.3으로 고정합니다. 앱은 DuckDB의 확장 자동 설치/자동 로딩을 끄므로 확장 다운로드에 의존하지 않습니다.

인터넷에 연결된 별도의 RHEL 8.10 x86_64 빌드 장비에 Python 3.12.14를 먼저 준비한 뒤:

```bash
bash scripts/build_offline_bundle.sh /absolute/path/to/new-bundle
```

생성된 `wheelhouse`, `runtime.lock`, `install_offline.sh`, `check_environment.py`, `README.md`, `SHA256SUMS`를 반입합니다.
`build-env`는 빌드용이므로 반입할 필요가 없습니다. 폐쇄망 대상에 승인된 Python 3.12.14가 설치되어 있어야 합니다.

```bash
cd /path/to/transferred-bundle
bash install_offline.sh /absolute/path/to/new-venv
/absolute/path/to/new-venv/bin/python -m cdw
```

Python wheel 외에 OS의 X11/xcb·OpenGL 런타임과 한글 글꼴이 필요합니다. OS 패키지는 위 번들에 포함하지 않습니다.
현장 점검은 `python check_environment.py`로 네이티브 모듈 import를 확인한 후, 그래픽 세션에서 앱을 실행하고 데모 수집을 수행합니다.
Qt 플랫폼 플러그인 오류는 `QT_DEBUG_PLUGINS=1 python -m cdw` 출력과 Qt의 `libqxcb.so`에 대한 `ldd`로 누락된 시스템 라이브러리를 확인하세요.
glibc를 시스템에서 임의로 교체하는 절차는 필요하지 않습니다. 이 저장소의 Windows 테스트와 wheel 해석만으로 실제 RHEL의 그래픽 런타임까지 검증되지는 않습니다.
